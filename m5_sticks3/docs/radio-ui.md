# Wi-Fi / BLE 图形分析界面

主菜单新增 **WIFI** 和 **BLE** 两张卡片，保留原来的 MOTION、AURA、SYSTEM、
WAVE 和 ARCADE。界面使用现有 135×240 竖屏与两个实体按键，数据来自通信模块的
线程安全快照；连接、扫描和开关操作进入主循环命令队列。

## 按键与导航

| 位置 | 短按 KEY1 | 短按 KEY2 | 长按 KEY2（至少 650 ms） |
| --- | --- | --- | --- |
| 主菜单 | 下一张卡片 | 打开选中页面 | 与打开动作相同 |
| WIFI / BLE 主页 | 切换底部动作 | 执行动作 | 返回主菜单 |
| 扫描列表 | 下一条结果，自动翻页 | 打开设备详情 | 返回分析主页 |
| 设备详情 | 切换连接 / 返回列表 | 执行选中的动作 | 返回扫描列表 |
| 链路 / 流量 / 服务页 | 下一页 | 下一页 | 返回分析主页 |
| 密码字符组 | 下一组 / 删除 / 保存 / 取消 | 打开或执行 | 取消编辑，返回设备详情 |
| 密码字符选择 | 下一个字符 | 添加字符，回到字符组 | 返回字符组，不添加字符 |
| 关闭无线确认页 | 取消 | 确认关闭 | 取消 |

页面底部始终提示按键。动作在释放 KEY2 时执行；一次长按只触发返回，不会再触发
短按动作。如果按住 KEY2 时扫描结果或选择发生变化，界面提示重试，防止释放时
连接到另一条结果。游戏页面的原有按键行为不变。

底部出现 **QUEUED** 表示请求已进入队列，随后查看连接状态、地址及错误信息。
入队成功不等于扫描完成、密码正确或网络已连接。

## WIFI 页面

主页显示当前连接状态、连接后的 RSSI（dBm）、频道、网络名称、IP、设备热点客户端
数量、重试次数和最近命令错误。底部信号条保留本次页面打开后的短时 RSSI 记录，
约每 350 ms 更新；没有有效 STA 信号数据时显示基线，不代表测得了 -100 dBm。

按 KEY1 可依次选择：

| 动作 | 功能 |
| --- | --- |
| Scan nearby | 发起一次附近 2.4 GHz Wi-Fi 扫描并进入结果页 |
| Last scan | 查看最近一次缓存的扫描结果 |
| Link details | 分页查看 STA、设备热点、BSSID、频道与状态 |
| Traffic / echo | 查看应用协议计数器和最近一次回显文本 |
| Reconnect saved | 使用已保存的 SSID / 密码重新连接 |
| Disconnect STA | 断开路由器连接并停止此次运行中的自动连接，保留凭据与设备热点 |
| Turn radio OFF / ON | 运行时关闭 / 开启 Wi-Fi；关闭前有设备上的确认页 |
| Local hotspot | 在实体屏幕上查看设备热点名称、IP 和热点密码 |

Wi-Fi 关闭时，设备热点及其 HTTP 访问也会中断。运行时开关和断开状态不写入 NVS，
重启后按编译配置启用无线功能，并使用已保存的 STA 凭据。连接新网络会先保存
SSID / 密码，再交给驱动执行；即使当次连接失败，保存的配置仍会用于后续重连。

### 扫描并连接网络

1. 打开 WIFI，选中 **Scan nearby** 并按 KEY2。
2. 等待扫描结束。列表最多保留 16 条结果，显示名称、RSSI、频道和安全类型。
   例如 -55 C6 WPA2 表示 RSSI 为 -55 dBm、频道 6、WPA2。
3. 用 KEY1 选中网络，KEY2 查看详情。详情显示完整名称、BSSID、频道、安全类型
   和信号强度；长名称会滚动。
4. 对开放网络选择 **Connect open AP**；对支持的个人密码网络选择
   **Enter password**。
5. 提交后查看 **Link details**。STA 显示 connected 且获得有效 IP 才说明连网成功；
   connecting / retry_wait 表示仍在尝试。错误码和重试计数可用于排查。

扫描列表在显示时固定，新的后台结果不会悄悄重排正在选择的设备；打开详情后，
连接目标还会另存一份。重新扫描或重新打开 Last scan 才获取新的列表。
实际配网按所选 SSID 和密码连接，不固定所选 BSSID；同一 SSID 有多个接入点时，
Wi-Fi 驱动可能选择其中另一台。详情里的 BSSID 用于分析该条扫描结果。
扫描过程中旧结果可能仍保留，顶部状态会标明正在扫描；这些结果是缓存，不是实时探测。

当前屏幕支持开放网络及 WPA2 / WPA3 个人密码网络。WEP、仅 WPA1、企业认证、
OWE 等未实现的认证方式会明确提示不支持。隐藏 SSID 可出现在列表里，但设备上
暂未提供手工输入 SSID 的界面，需要使用外部客户端配网。

### 双按键输入密码

密码编辑有两层选择，覆盖全部可打印 ASCII 字符（空格以及字符 33–126）：

1. KEY1 选择字符组：a–m、n–z、A–M、N–Z、数字、各组标点或 SPACE。
2. KEY2 打开字符组，KEY1 选择具体字符，KEY2 添加字符。
3. 添加后回到刚才的字符组，可继续输入。顶部以星号和长度显示已输入内容。
4. 在字符组列表中选择 **Delete last** 删除最后一个字符。
5. 输入完成后选择 **Save + connect**；选择 **Cancel** 或长按 KEY2 可取消编辑。

受保护网络要求 8–63 字节密码，或 64 位十六进制 PSK；保存前会校验。
设备编辑器只输入 ASCII。含 UTF-8 字符的 SSID 会保留扫描所得的原始字节用于连接，
但现有字体将非 ASCII 字节显示为占位符；这不会改变实际连接目标。需要输入 UTF-8
密码时，可以使用外部 Python 客户端或 HTTP / BLE 配网接口，长度限制按 UTF-8 字节计算。

**Local hotspot** 显示的是设备自己建立的热点密码，不是已保存路由器的密码。
API 令牌仍从 USB 启动日志读取；热点密码和令牌都不会通过无线查询接口返回。
离开密码编辑器会清除编辑缓冲区。

## BLE 页面

BLE 主页区分两个角色：

- **Phone / server**：手机或电脑连接设备提供的 NUS GATT 服务，发送查询、echo 等命令。
- **Peer / client**：设备主动连接一个附近可连接的 BLE 广播设备，发现其主服务。

默认最多同时维持一个 NUS 客户端连接和一个主动外连连接。主页显示两类连接状态、
NUS 加密 / 配对状态、接收 / 丢弃计数和最近错误。信号历史条使用主动外连设备的
RSSI；Link details 分别展示 NUS 状态和外连地址、RSSI、MTU、服务数与错误码。

| 动作 | 功能 |
| --- | --- |
| Scan nearby | 扫描附近 BLE 广播设备 |
| Last scan | 查看最近缓存的 BLE 扫描结果 |
| Link details | 在 NUS 服务端连接与主动外连信息之间翻页 |
| Traffic / echo | 查看共享协议计数与回显 |
| Peer services | 分页查看外连设备的主服务 UUID，最多缓存 8 项 |
| Disconnect peer | 断开主动外连设备；不会单独断开 NUS 手机 / 电脑连接 |
| Turn radio OFF / ON | 关闭 / 开启 BLE；关闭会断开两类连接，保留已保存配对 |

扫描结果最多保留 16 条，显示名称、地址、RSSI 和是否可连接。选择一条结果进入详情，
对可连接设备选择 **Connect device**。随后查看连接状态与 Peer services；
仅广播的 beacon 会显示不能连接。外连过程只发现主服务，不对陌生设备写入属性。
主动外连失败后可查看错误并手动重试；随机地址可能会变化，重扫后重新选择即可。

这里扫描的是 **BLE 广播**，不是经典蓝牙设备清单。没有正在广播、超出范围或不可发现的
设备不会出现。主服务 UUID 分析也不等于已经实现该设备的全部业务协议、蓝牙音频、
串口 SPP、任意特征写入或通用文件传输。

原有 NUS 通道保持加密读写、持久配对、长响应读取与 ready 通知。该加密状态显示
针对 NUS 连接，不表示所有外连设备都已完成配对。完整协议见
[通信框架文档](connectivity.md)。

## Traffic / echo 的统计口径

WIFI 和 BLE 的 Traffic 页面共享一份应用协议统计：

- HTTP / BLE 请求数量。
- RX / TX 的 JSON 请求与响应字节数。
- 最近的传输通道、操作名、请求 ID 和结果。
- 命令完成 / 拒绝计数，以及最近一次 echo 的前 64 字节显示内容。

这些计数来自公共命令处理器，不含 HTTP 头、TCP / BLE 协议开销、无线重传、
广播报文、所有射频包或底层吞吐率；BLE 主服务发现也不计入 NUS JSON 流量。
设备重启后计数重新开始。本地按键命令会进入完成计数，但不算 HTTP / BLE 请求。
回显页面用于显示应用实际收到的 echo，非 ASCII 和控制字符会转换为安全的显示占位符。

可在电脑上发出回显，再查看设备页面：

~~~bash
python tools/connectivity_client.py --url http://192.168.4.1 echo "hello from LAN"
python tools/connectivity_client.py --ble <设备的BLE地址> echo "hello from BLE"
~~~

## 开发与验证

正式固件不自动扫描、连接陌生设备或导出屏幕数据。只有显式开启
M5_STICKS3_RADIO_SMOKE_TEST 的独立测试构建才会自动巡检页面并进行真实扫描；
它不会主动连接扫描到的设备。启用 CONFIG_LV_USE_SNAPSHOT=y 后，测试构建还会
通过串口导出 RGB565 页面帧，用于视觉检查。该开关不能与原有
M5_STICKS3_HW_SMOKE_TEST 同时启用；测试完成后应重新烧录正式固件。

### BLE 配对与持久化边界

本轮修复了 REPEAT_PAIRING 早于 CONNECT 到达时误拒绝同一连接的问题，并让重复请求
启动广播保持幂等；正常主动断开不再作为错误显示，原始断开原因仍保留在串口日志。

针对 ESP-IDF 5.5.4 默认 config store 对同一 peer 的安全记录原位更新可能只改 RAM、
未写入 NVS 的行为，新增适配器组合其公开读、删、写回调：安全值不变时跳过写入；
需要更新时执行删除再写入。操作失败会尝试回滚并锁存错误，关闭 BLE 活动、拒绝
GATT 访问；需要完整重启后再尝试，单纯运行时重新开启不会清除错误。

这两个 NVS 操作不是掉电原子事务，中途断电可能需要重新配对。适配器只更新对应
peer 的安全记录，不批量清除其他 peer 或用户 NVS。不能据此保证掉电时保留一次
尚未完成的配对更新。

### 共存配置

当前将 Bluetooth Controller 与 NimBLE Host 放在 **Core 1**，Wi-Fi 协议栈放在
**Core 0**，并开启软件共存。这符合 Espressif 对双核任务分配的建议，用于减少
协议栈任务之间的竞争；Wi-Fi 和 BLE 的 2.4 GHz 射频仍通过时分方式共享。
参见 [ESP-IDF 5.5.4：ESP32-S3 RF Coexistence](https://docs.espressif.com/projects/esp-idf/en/v5.5.4/esp32s3/api-guides/coexist.html#setting-coexistence-compile-time-options)。
